# VeeInvite

AI-designed wedding websites. Couples complete a 6-step quiz, Claude
designs a visual identity, and guests RSVP on the resulting page.

## First-run setup

```bash
# 1. Install dependencies
npm install

# 2. Provision Supabase
#    - In the Supabase dashboard, open SQL editor and run:
#      supabase/migrations/001_init.sql
#    - In the Supabase dashboard, create a public Storage bucket
#      named "wedding-sites" (5MB limit).

# 3. Configure environment
#    .env.local is already populated. If you start fresh, copy
#    .env.example and fill in the values.

# 4. Run the dev server
npm run dev
```

Then open [http://localhost:3000](http://localhost:3000).

## Verify the pipeline

Without any external network access (no Supabase, no Claude), you can
still verify the validator + renderer work:

```bash
npx tsx scripts/verify-pipeline.mjs
```

## The 60-second tour

- `CLAUDE.md` — context file for any AI working on the project.
- `CONTEXT.md` — quick onboarding.

- `docs/DECISIONS.md` — decision log.

- `src/lib/` — types, validator, renderer, AI layer, pipeline helpers.
- `src/app/api/` — generate, edit, structured, rsvp.
- `src/app/w/[slug]/route.ts` — serves raw HTML to guests.
- `src/components/dashboard/` — preview, editor, chat, RSVP table.

## Rules that must never be broken

1. The app name is VeeInvite — not Aisle.
2. Never modify `skeleton/wedding-skeleton.html` casually.
3. `theme_json` is the source of truth. HTML is derived.
4. `injectStructured()` always runs **last** in `buildSite()`.
5. The validator never throws.
6. The RSVP form structure is never generated by AI.
7. All Claude calls are server-side only.
8. `/w/[slug]` returns raw HTML, not a Next.js page.
9. AI never sets layout CSS (display, position, grid-*, gap, etc).
10. Commit format: `Phase N complete: description`.

## Deployment

settings. Set `NEXT_PUBLIC_APP_URL` to your production URL.
