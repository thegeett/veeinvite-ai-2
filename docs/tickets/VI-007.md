# VI-007: API Routes

## Summary
Build the four API routes: generate, edit, structured, rsvp.

## Background
All Claude API calls live server-side here. `/api/generate` and
`/api/edit` are the heavy orchestration routes; `/api/structured`
intentionally skips Claude and just re-renders from the saved
`theme_json`; `/api/rsvp` is public and auth-free.

## Work Required
- `src/app/api/generate/route.ts` — end-to-end initial build.
- `src/app/api/edit/route.ts` — instruction-driven regeneration.
- `src/app/api/structured/route.ts` — direct DB update + re-render.
- `src/app/api/rsvp/route.ts` — insert guest RSVP (no auth).

## Technical Notes
- Service-role client is used to upload HTML to Storage in the
  generate/edit routes (we already verified ownership via the
  logged-in client before that point).
- `structured` route enforces a whitelist of allowed columns to
  prevent SQL-column injection.

## Acceptance Criteria
- [x] `/api/generate` returns `{ success, siteUrl, themeJson }` on success.
- [x] `/api/edit` appends the instruction to `style_history` and regenerates.
- [x] `/api/structured` only accepts whitelisted fields and re-renders if
      `theme_json` + `site_html_url` already exist.
- [x] `/api/rsvp` works without auth and validates required fields.
- [x] Each route returns 500 with a JSON error body on failure.

## Dependencies
VI-002, VI-003, VI-004, VI-005, VI-006.

## Definition of Done
Tested locally, the four routes handle happy path and error paths
correctly.
