# VI-011: Public Wedding Site Route

## Summary
Serve the raw HTML wedding site at `/w/[slug]`. This is a route
handler, not a Next.js page — the HTML is returned directly with a
`text/html` Content-Type and no app-shell wrapping.

## Background
Guests should experience a polished wedding website, not an app
wrapper around one. The HTML is already self-contained in Storage;
we just need to fetch it and pipe it through.

## Work Required
- `src/app/w/[slug]/route.ts` — route handler:
  - Look up the couple by slug using a service-role client.
  - 404 page for unknown slugs.
  - "Coming soon" page for unpublished sites.
  - Fetch `site_html_url` and return the body with
    `Content-Type: text/html` and `Cache-Control: public, max-age=300`.

## Technical Notes
- Service-role client bypasses RLS, which is appropriate here because
  the route is public.
- The RSVP form posts to `/api/rsvp` — the skeleton already does this.

## Acceptance Criteria
- [x] Route handler returns raw HTML (not a Next.js page).
- [x] Content-Type is `text/html`.
- [x] Unknown slug returns a simple 404 HTML page.
- [x] Unpublished couple returns a "coming soon" HTML page.
- [x] Published couple returns the full stored HTML.

## Dependencies
VI-005, VI-006.

## Definition of Done
Guest visiting `/w/[slug]` sees the wedding site and can submit an
RSVP that appears in the couple's dashboard.
