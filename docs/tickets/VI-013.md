# VI-013: End to End Testing and Bug Fixes

## Summary
Static verification of the pipeline and a documented list of manual
checks for the developer's first run.

## Background
The initial build environment (Cowork sandbox) had no outbound
network to npm, GitHub, Supabase, or the Anthropic API. We could not
install dependencies or run the real end-to-end flows there. Instead,
we verify as much as possible statically and document the remaining
checks.

## What was done in this phase
- `scripts/verify-pipeline.mjs` exercises the validator + renderer
  pipeline end-to-end with synthetic inputs and passes.
  - `validateAll(null)` returns complete defaults without throwing.
  - Forbidden CSS layout properties are stripped.
  - Unapproved fonts are replaced.
  - Dangerous values (`javascript:` URLs) are rejected.
  - `buildSite()` produces HTML with no remaining placeholder tokens,
    with the stylesheet injected and structured data winning over
    anything AI-written.
- `tsconfig.pipeline.json` typechecks the pipeline modules (passes
  once `@types/node` is installed).

## Manual checks for first run (developer)
Run these after `npm install` + running the SQL + creating the
Storage bucket.

1. `npm run dev` boots on port 3000.
2. Visit `/` — landing page renders with VeeInvite branding.
3. Sign up at `/auth/signup`. Redirects to `/onboarding`.
4. Complete the quiz with the provided test couple. Submit.
5. Loading screen cycles messages. Generation completes (~10-15s).
6. Dashboard renders with the iframe preview and couple's names.
7. Edit person1_name via StructuredEditor → preview reloads fast, no
   Claude call.
8. Send a chat edit like "Make it more romantic with warm tones" —
   preview reloads with redesigned site.
9. Copy the site URL and open it in a new tab. Because the couple is
   now `is_published = true`, the wedding page loads.
10. Submit an RSVP as a guest. See it appear in the RSVP table.
11. CSV export downloads.
12. Sign out → sign in → reach dashboard.
13. Edge cases: visit `/w/nonexistent-slug` (404 page), try
    `/dashboard` while signed out (redirect to login), POST
    `/api/rsvp` with no email (400).
