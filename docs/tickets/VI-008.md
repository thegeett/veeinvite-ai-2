# VI-008: Authentication

## Summary
Email/password signup and login, plus middleware that protects the
app routes while leaving the public wedding site and landing page open.

## Background
Auth is intentionally minimal. The middleware is the gate: it redirects
unauthenticated visitors away from `/dashboard` and `/onboarding`, and
ensures the auth cookie is refreshed on every request.

## Work Required
- `src/app/auth/signup/page.tsx` — email + password + confirm.
- `src/app/auth/login/page.tsx` — email + password.
- `src/middleware.ts` — protect `/dashboard/*` and `/onboarding/*`;
  always leave `/w/*`, `/auth/*`, `/api/rsvp`, and `/` open.

## Technical Notes
- Use `@supabase/ssr` middleware pattern so the auth cookie refreshes
  on every request without the developer writing that code.

## Acceptance Criteria
- [x] Signup redirects to `/onboarding` on success.
- [x] Login redirects to `/dashboard` on success.
- [x] Invalid credentials show an inline error.
- [x] Middleware redirects unauthenticated users from `/dashboard`.
- [x] `/w/[slug]` remains reachable without auth.

## Dependencies
VI-006.

## Definition of Done
A new user can sign up, get redirected to `/onboarding`, sign out,
sign back in, and reach `/dashboard`.
