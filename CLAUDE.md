# CLAUDE.md — AI context for VeeInvite

## What this project is
VeeInvite is an AI-native wedding website builder. A couple completes a
6-step quiz, the AI designs a complete visual identity for their site,
and guests visit the resulting URL to RSVP.

## The single most important idea: the CSS JSON pipeline
All generated sites share one pre-built HTML skeleton that lives at
`skeleton/wedding-skeleton.html`. The AI never writes HTML — it only
returns a JSON object describing design tokens, particle effects, and
copy. The renderer injects that JSON into the skeleton and saves the
result to Supabase Storage.

```
[skeleton.html]  +  [couple data]
     │                    │
     └────── prompt ──────┘
                 │
            Claude call
                 │
           ThemeJSON
                 │
            validator (never throws — bad values get defaults)
                 │
            renderer
                 │
            final HTML → Supabase Storage → /w/[slug]
```

## Architecture at a glance
- Next.js 14 App Router + TypeScript (strict)
- Supabase Postgres + Auth + Storage (bucket: `wedding-sites`)
- Anthropic Claude (`claude-sonnet-4-5`)
- Tailwind (app UI only — never injected into the skeleton)
- theme_json in the database is the source of truth; the HTML is derived.

| File | Purpose |

| `src/components/dashboard/*` | Preview, structured editor, AI chat editor, RSVPs. |

## Rules that must never be broken
1. The app name is VeeInvite — not Aisle.
2. Never modify `skeleton/wedding-skeleton.html` after Phase 0.
3. `theme_json` is the source of truth. HTML is derived.
4. `injectStructured()` runs **last** in `buildSite()` — real data always overwrites AI copy.
5. The validator never throws. Bad values get safe defaults.
6. The RSVP form structure is never generated by AI.
7. All Claude API calls are server-side only.
8. `/w/[slug]` returns raw HTML, not a Next.js page.
9. AI never sets layout CSS properties (display, position, flex-direction, grid-template-*, width/height, gap, etc).
10. Commit after every phase: `Phase N complete: description`.

## How to run
```bash
npm install
# Run the SQL in supabase/migrations/001_init.sql inside the Supabase SQL editor.
# Create a public Storage bucket named "wedding-sites" in Supabase.
npm run dev
```
